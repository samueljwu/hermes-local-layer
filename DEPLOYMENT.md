# Deployment and Routing

This file is the source of truth for local public-route ownership. Subsystem READMEs should refer here rather than restating route mappings.

Canonical manifest: `routes.yaml`.

## Current routes

| Route | Filesystem path | Owner | Contract |
| --- | --- | --- | --- |
| `/` | `/home/hermes/homepage/dist` | `homepage` | Static/generated root landing page artifact. |
| `/feed/` | `/home/hermes/homepage/dist/feed` | `feed` | Generated picks page rendered from feed-local recommendation history; served by the root homepage mapping. |
| `/wiki/` | `/home/hermes/wiki/dist` | `wiki` | Generated VitePress site from `wiki/src`; do not edit `dist` directly. |
| `/stocks/` | `/home/hermes/stock-screener/site/dist` | `stock-screener` | Generated static stock review pages. |

## Ownership rules

- `routes.yaml` owns route-to-path facts.
- `homepage/` is classified as a generated/static artifact container, not a full subsystem like wiki, journal, tasks, feed, repo-scout, or stock-screener.
- `homepage/dist/index.html` may be edited/regenerated only as the public landing artifact.
- `/feed/` is generated by the feed harness into `homepage/dist/feed/index.html`; feed remains the data owner.
- `/wiki/` is generated by VitePress from wiki source. Wiki docs should describe source and build commands, then point to this file for serving paths.
- `/stocks/` is generated by the stock-screener workflow. Stock-screener docs should describe generation, then point to this file for serving paths.

## Change procedure

1. Update `routes.yaml` first.
2. Update this file if route semantics changed.
3. Update only brief references in subsystem READMEs.
4. Run the relevant subsystem validation/build command before relying on the live route.
